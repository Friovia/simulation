# bench/wasm-poc — Rust→WASM PoC（2026-10-17）

回答一个问题：README 翻转条件里的 Rust→WASM，真到了那天能拿到什么？
用一份 P0 形态的真实物理（不是 fibo 微基准）实测。

## 方法

- **孪生实现**：`ts/physics.ts` 与 `rs/src/lib.rs` 逐操作对齐——泵 H(Q)=h0−aQ²、
  供回液管、10 条并联冷板支路，Haaland 摩阻 + 层流 64/Re、PG25 物性**占位**线性拟合
  （非生产数据）、外层对支路压降二分 60 次 × 内层支路流量二分 40 次，全部**定长迭代**，
  保证两实现的浮点执行序列同构。
- **确定性**：FNV-1a 哈希输出字节；MC 用同一条 LCG 轨迹（h0±5%、支路 K±20%），
  10⁴ 采样比 min/max。
- **公平性**：预热后取 5 轮最优；TS 与 WASM 同输入同输出布局。

## 复现

```bash
# Rust 工具链（国内源已配 ~/.cargo/config.toml + RUSTUP_DIST_SERVER=rsproxy.cn）
cd rs && cargo build --target wasm32-unknown-unknown --release
cd .. && node ts/run.ts   # V8
       bun  ts/run.ts     # JSC（跨引擎对比）
```

## 结果（2026-10-17，Win11 x64，rustc 1.99.1，单机单输入，JIT 预热取最优）

| 指标 | V8-TS | V8-WASM | JSC-TS | JSC-WASM |
|---|---|---|---|---|
| 单次求解（10 支路） | 1171 µs | 613 µs | **473 µs** | 573 µs |
| WASM/TS | — | 1.9× | — | **0.8×** |
| MC 10⁴ 样本 | 15.1 s | — | 6.5 s | 8.1 s（批内循环） |
| 输出哈希 | `ef55213f` | `ef55213f` | `ef55213f` | `ef55213f` |
| MC min/max 位级 | 一致 | 一致 | 一致 | 一致（四方相同） |

物理自洽：Q=200.8 L/min、支路压降 15.8 kPa，泵头=ρg·2.80 m=干管+支路压降，
守恒残差 5.5e-12。

## 结论

1. **"换语言≈10×"在本负载不成立**：标量、超越函数（log10/pow）密集、无 SIMD 空间的
   求解器，WASM 只有 0.8–1.9×，JSC 的纯 JS 甚至更快。10× 神话属于数组/SIMD/并行负载。
2. **真正的性能杠杆是算法**：本 PoC 故意用保守二分（60×40 次定长迭代保确定性）；
   牛顿化预期拿一个数量级，比换语言大得多。蒙特卡洛要进交互，先改算法。
3. **位级确定性实测成立且超预期**：TS/WASM × V8/JSC 四方输出与 10⁴ 样本 MC 全部位级
   一致——但这是四家 libm 在本用例上的巧合，不是规格；规格级保证只有 WASM 单二进制能给。
4. **JS 的性能也是引擎相关的**：同一份 TS 代码 V8/JSC 差 2.5×；WASM 的耗时跨引擎稳定
   （613/573 µs，8.19/8.13 s）——性能可承诺性也是 WASM 的资产。

## 对翻转条件的反馈（已写回主 README）

- (a) 蒙特卡洛：语言移植不解决 10⁴×毫秒的问题，先牛顿化；
- (c) 位级一致：确定性优势实测为真，且额外拿到"性能跨引擎稳定"。
